# 世界切片发布规则

仓库 aitestforbolin/aitestforbolin-Personal-blog，分支 main，日期使用 Asia/Shanghai。每天北京时间 06:00 独立执行。每期固定五条，五条核实完成后一次发布。

## 选材

读者想在日常浏览中遇见自己原本想不到去搜的事，慢慢对不同地方形成自己的印象。选稿时问一句「读完这条，我对这里的人怎样过日子多懂了什么？」原文里一个有来由的做法、一次选择、一个前后变化，或一组能纠正印象的数字，都可能给出答案。保留吃食、亲情和偶然发现的乐趣，也看普通人遇到的代价和门槛。

### 主题库

世界切片以七个互斥大类作为选题入口。括号内二十二个小项及其具体细节全部作为搜索线索，不得省略。

1. **工作、收入与财富**（就业与职业机会：外国人是否容易找到工作、白领和蓝领机会、行业需求、裁员、职业天花板、兼职与零工收入；工资与实际生活水平：税前税后工资、最低工资、普通人的购买力、夫妻收入、一个家庭能否留下结余；工作制度与劳动保障：工作时间、带薪年假、病假、失业金、工作生活平衡、雇员受到怎样的保护；税收与财富积累：工资税、股票和加密资产税、储蓄能力、住房资产、家族财富和代际传承）。核心看普通人靠什么谋生、干得多累、税后能攒下多少钱。
2. **住房与生活成本**（住房与租房负担：房源短缺、合租、押金、房租收入比、买房难度、Airbnb 和旅游业对当地住房的影响；生活成本：食物、交通、水电、医疗、育儿等日常开支，以及一个人每月需要多少钱；旅游、全球化与本地居民：旅游业、外国企业、数字游民和外来资本怎样改变房租、就业和当地生活）。核心看住不起、物价上涨、外来资本和旅游业怎样挤压本地人的日常开销。
3. **签证、身份与准入门槛**（签证与入境路径：工作签证、数字游民签证、留学、陪读、打工度假、经营签证等进入一个国家的方式；永居、公民身份与政策收紧：永居年限、收入要求、社保缴纳、语言考试、能否换工作以及移民政策变化；语言与职业门槛：英语是否够用、当地语言需要达到什么程度、学历和职业资格是否被承认）。核心看外国人进不进得去、留不留得下、语言和资质卡得有多严。
4. **教育、医疗与社会保障**（教育与育儿：公立和私立教育、国际学校、大学费用、托育成本、育儿假、儿童教育方式；医疗、养老与社会保障：医疗费用、保险、养老金、福利资格，以及外国人能否真正享受这些制度）。核心看养娃贵不贵、看病难不难、福利制度到底兜不兜底。
5. **社交、融入与日常文化**（外国人的融入与歧视：种族、国籍、外貌和身份是否影响求职、租房、约会及日常交往；交朋友、孤独与社区关系：当地人是否愿意接受新朋友、社交圈怎样形成、小国家和大城市的社交差异；饮食、消费与生活习惯：集市、超市、咖啡馆、小费、酒精、饮食结构、外貌文化等具体日常生活）。核心看真住在当地舒不舒服、容不容易孤独、有没有隐形排外和文化摩擦。
6. **城市环境、基建与治安**（交通、数字化与城市生活：公共交通、骑车、步行、汽车依赖、政府办事效率、电子支付、绿地和宠物环境；气候与环境：高温、冬季日照、空气污染、噪声、雾霾，以及这些因素怎样影响长期生活；治安与社会稳定：犯罪、枪支、骚乱、示威、警察存在感以及普通人的安全感；城市与地区差异：首都和普通城市、旅游城市和非旅游城市、南北地区之间的工资、机会与生活差距）。核心看交通、办事效率、天气、安全感等物理居住体验，以及首都和普通城市的落差。
7. **宏观趋势、政治与社会情绪**（政治、权利与公共情绪：新闻自由、少数群体权利、移民争议、政府支持度、社会是否开放宽容；经济与产业前景：通胀、利率、经济增长、债务、制造业衰退、外资和产业变化；青年处境与人口变化：青年失业、低工资、出国潮、生育率、人口流失，以及年轻人是否还相信本国未来）。核心看一个国家是在往上走还是往下滑、年轻人还有没有盼头、社会氛围是开放还是紧绷。

**先选主题，再面向全球找来源。** 开始时读取昨日归档和近 14 天归档。先按正文主线把昨日五条分别归入一个且仅一个主大类和一个且仅一个主小项。当天从七个大类中选出五个不同大类，每个大类最终只入选一条；当天五条的主大类必须互不重复。当天候选的主小项不得与昨日五条的主小项重复。一个材料即使涉及多个主题，也只按最能解释正文主线的一个主小项计数，不能通过更换标签规避重复。主题归类只用于后台选稿检查，不在网站显示。

用主题库提出普通人实际面对的问题，再面向全球搜索合适材料，不受现有国家笔记或往期国家名单限制。第一轮可从主题词、具体生活问题和当地语言展开开放搜索，由线索找到当地报道、公开访谈、社区材料、办事说明或调查原文。不要用固定媒体名单、固定域名或往期来源清单启动搜索。地理多样性用于候选比较：材料同样好时，优先近期较少出现的地区、城市和人群。以前用过的媒体可以在核实具体线索时引用，也可以收录它恰好报道的合适稿件。

**再从候选中选五条。** 每日先粗筛约 20～30 条，先完成主大类和主小项归类，再全文阅读并核实最有潜力的稿件。最终五条必须来自五个不同大类，并通过“昨日未出现同一小项”的检查。优先近几个月的慢内容，采用较早的规则或统计时确认其仍适用。活动或服务公告如果只交代时间、地点和报名方法，顺着线索找一找实际怎么参与、为什么有这个做法，或它给谁带来了什么变化。定稿前把五条与近期选题对照，避开相同事件。遇到与近期很相似的店铺服务或社区活动，把它与其他地方、其他来源的候选再比一次。同一地点若能呈现此前少见的人、处境或做法，仍值得选。材料同样好时优先近 14 天较少出现的小项，以及少见的地区、人群和来源。候选不足时继续更换主题关键词、地区和当地来源，从近几个月的材料中找齐五条；不能用与昨日重复的小项或同日重复的大类凑数。

2026 年 11 月 23 日读者挑出的旧稿可用来比较读感。节前卖牲畜筹钱、给姐姐挑花布、员工餐变成招牌、一起修旧物、做泡菜和用公炉烤面包，都讲清了一个具体做法。涨租后合住、上班路费吃掉一大截工资、骑车十三公里去实习、出狱后靠咖啡馆的工作租到房，让人看见了生活中的选择和后果。居民为供水发声、外婆用转来的天数领育儿津贴、一笔 400 美元的意外账单怎么付，也能从一个细节读懂公共生活。用这些例子校准选稿，题目和地点由当日发现的材料决定。

标题讲具体发生什么。正文先想清楚这一条到底要讲哪件事，再按中文读者理解事情的顺序写出来，不能逐段摘取原文信息后拼接成摘要。不机械规定句数或字数，讲清就收。必要时分成两个短段落，用空行分隔。人名、地名、机构名只有影响理解才保留；陌生节俗或术语用一句普通中文解释，不能只丢出音译词。数字、旁观者评论和背景材料，只有推进这件事才写，不能因为原文出现就塞进末尾。句子间要有清楚的时间、因果或转折关系，主语自然延续，不来回跳人物。朗读一遍：如果像资料摘录或翻译腔，就整段重写，不靠增加连接词补救。页面只显示地点、材料日期和原始链接，证据类型和依据留在后台数据，不显示“看依据”或核验过程。一个日常细节足以说明一个生活问题即可。读感以第001期澡堂镜面广告、南非送水车、育儿津贴为例。勿为罕见或戏剧性而选稿，勿用抽象结论收尾。统计需要解释多个指标才能明白的题目可以留待专题。

## 事实

搜索摘要提供线索。选入的每项说法都必须读到支持它的原文。区分记者所见、当事人判断、经营者自述和官方规定。个人经历只适用于当事人。全国趋势需统计，义务或权利需当前官方规则。规则与医疗等高影响主张核对可靠原始来源。对因果解释标明是谁的判断。不能读到正文就继续找别的材料。

每个来源 evidence 保存关键段落简述、数据表号或条款位置，便于回查。不要复制全文。日期精确到原文可确认的程度，允许 YYYY-MM。不要把收录日写成素材发布日期。

## 发布

全部远端 GitHub 读写使用 GitHub Connector。开始读取本规则、data/world-notes.json 和 data/world-notes/index.json，按索引读近14天归档。当日归档已存在时验读页面，勿重新选稿或覆盖。

生成请求 data/world-notes-publish-request.json。requestId 使用唯一安全字符标识，payload 的 schemaVersion=1，reportDate=上海当天，items 长度必须为5。每条包含 id、title、body、location、materialDate、evidenceType、category（数据/规则/报道/个体）、sources；image 可省略或设为 null。取得并核实图片时，image 为对象，必须包含 https url、sourceUrl（图片所在原文页）、alt（中文画面描述）、credit（原署名）、caption（简短中文图注）。sources 每项包含 publisher、https url、evidence。id 稳定，推荐日期加主题英文短名。不得设置 initialEdition。

提交后等待 Publish World Notes Action 成功，回读当天归档、最新版和索引，确认 requestId 与条目一致。脚本 scripts/publish_world_notes.py 是结构校验依据。Action 一次提交写入三者，近14天按ID和标题去重。语义事实核验由写稿任务负责。

GitHub Actions 的机器人提交可能不会触发分支模式的 Pages 构建。确认归档成功后，通过 Connector 更新 data/world-notes-deploy-trigger.json，内容为 reportDate、requestId、verifiedAt。该正常提交触发站点构建。若重跑，先查是否已经存在同 requestId 的部署触发与成功的公开页面，避免重复写入。

待公开站点 https://aitestforbolin.github.io/aitestforbolin-Personal-blog/ 的 data/world-notes.json 和 data/world-notes/archive/YYYY-MM-DD.json 回读一致，再在会话返回今日标题和 world-notes/?date=YYYY-MM-DD 链接。未核到公开数据，报告部署待确认并继续检查或安全重试。不能用后台归档成功代替上线确认。

不发布一至四条的半期内容，不用旧稿或未核实内容凑数。扩展检索后仍不足五条时，保留上一期与真实日期，报告本次未完成及具体阻塞，并在本次任务内继续尝试恢复。来源大面积打不开时报告采集失败；程序或部署失败报告具体阶段，继续恢复。更正已发布事实需保留更正说明和版本记录。

首周保留实际启动、上线时间、原文可读性、合格条数与失败原因，观察持续可用性。用户读感反馈用于改进下一期。

## 网站阅读形式

首页参照 X 讯息：只展示本期五个标题，每个标题链接到当期阅读页的对应条目，另有整期入口。阅读页按顺序完整呈现五条，有合适图片时显示配图，无图时图片区域留空、正文照常；电脑上左文右图，手机上标题、图片、正文依次排列，保留清晰标题和舒适正文行距。不要显示内容分类筛选、折叠依据或核验文字，保留来源原文链接。历史已发布期数按真实条数展示，不伪造五条。

## 2026-11-12 行文校准

读者反馈的是文字本身读起来奇怪，不是页面设计。原稿的问题是无用的英文全名、未解释的音译术语、人物切换与松散细节拼接。不要把“有具体细节”等同于罗列细节。

网球稿围绕“免费学球的孩子如何来到球场、找到装备”展开，删去创办者英文全名和无助主线的每次人数。节日稿围绕“去姐姐家过节前买什么礼物、为什么这样选”展开，解释额头点吉祥痣的习俗，删去无关的商贩质量评论。范文以 data/world-notes/archive/2026-11-12.json 最新修订正文为准。

## 2026-11-13 配图

每条正文优先配一张相关真实图片，配图为可选项。选稿核实原文时一起选图：优先原报道内与该条人物、物件或地点直接相关的照片；公共机构活动页配图也可。不能只抓 og:image 而不检查，须打开图片核对画面与原图注，避开网站标识、广告和同文其他地区的照片。原报道无合适图片时，可寻找同地点的官方或开放许可图片，并明确标注为环境配图，不冒充当事人或现场。不使用 AI 生成的新闻现场图，不为方便找图牺牲选材质量。

记录图片原署名、来源页和中文图注；保留水印，不暗示拥有版权。使用发布方公开允许展示的图片、公开分享预览或有适用许可的图片；有禁止转载/外链等限制时换用合适的开放图片。默认链接发布方公开图片地址，不复制大图入仓库。只为实际读取并核实画面、署名和来源的图片填写 image。某篇网站无法提取图片、图片打不开、防盗链、缺署名或无法完成画面核对时，该条省略 image 或设为 null，直接继续发布五条已核实正文；不得因此中断整期。浏览器不可用时也按无图处理，不等待工具恢复。发布后可检查已附图片；失败则隐藏图片区域，正文照常阅读。图片检查不作为发布或上线成功的门槛，不捏造图片。

首页仍只展示标题。阅读页图片下方只留简短图注、图片署名与原文链接。图片可点击打开原文；若日后图片失效，隐藏图片区域，正文和原文链接继续可读。历史无图期数继续正常显示，不修改旧新闻事实。本次为11月13日五条补图，保留既有标题、正文、来源、requestId和发布时间；版本记录为本次 Git 提交。

## 2026-11-17 发布降级与失败通知

五条正文及来源核实完成即可提交发布请求，配图独立降级。先提交再验收，不能因浏览器或公开页面预检失败而停止交稿。公开 JSON 验收可使用可用的 HTTP 客户端或网页读取工具，不强制依赖可视浏览器。公开回读失败时区分“仓库已发布、部署待确认”和“未提交/发布失败”，检查 Action 和部署并安全恢复，不重复覆盖已存在的归档。

本次运行无法完成发布、Action/部署失败，或最终无法确认公开上线时，必须通过 Gmail 给用户自己（to=me）发一封单独故障邮件；会话回复不能代替邮件。主题为“世界切片未发布/发布待确认｜YYYY-MM-DD”，正文写明日期、失败阶段、已确认的原因、是否已写入仓库、当前可读期数链接及已采取的恢复动作。发送后按返回的邮件 ID 回读核验；报错先搜索确认是否送达，未送达再重试一次。仍失败则在运行记录和会话明确说明通知发送失败。当天同一故障邮件已发送时避免重复；故障恢复后可在该通知中回复恢复结果。

运行记录分别保存 textVerifiedCandidateCount、图片缺失原因、publicationAttempted、公开验收状态和通知邮件 ID。不能把缺图记为文字不合格，也不能把“任务正常结束”当作“栏目发布成功”。
