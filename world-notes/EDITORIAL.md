# 世界切片发布规则

仓库 aitestforbolin/aitestforbolin-Personal-blog，分支 main，日期使用 Asia/Shanghai。每天北京时间 06:00 独立执行。每期固定五条，五条核实完成后一次发布。

## 选材

读者希望顺手接触国外日常生活，逐渐形成丰富、准确的世界印象。读者无需提供关键词、维护渠道或完成阅读练习。先逛当地媒体社区、教育、交通、人物版与居民办事说明，再顺线索找公开原文。主要入口可从 GroundUp、The Korea Herald、The Kathmandu Post、Mexico News Daily、当地公共机构、Eurostat、OECD 开始。固定入口仅供发现，遇到新的好来源可继续使用。

每日先粗筛约 20～30 条，全文阅读最有潜力的候选，精选恰好五条不同的生活切片。候选不足时扩展当地媒体、地区与近几个月的材料，继续检索，直到凑齐五条已核实的稿件。优先近几个月的慢内容；旧规则与统计确认仍适用。读近 14 天归档，避免相同事件，质量相近时优先少出现的地区、人群和生活领域。留意普通生活、代价和门槛，给平淡但能增进理解的细节机会。无需冷暖、地区、来源类型的每日配额。

标题讲具体发生什么。正文先想清楚这一条到底要讲哪件事，再按中文读者理解事情的顺序写出来，不能逐段摘取原文信息后拼接成摘要。不机械规定句数或字数，讲清就收。必要时分成两个短段落，用空行分隔。人名、地名、机构名只有影响理解才保留；陌生节俗或术语用一句普通中文解释，不能只丢出音译词。数字、旁观者评论和背景材料，只有推进这件事才写，不能因为原文出现就塞进末尾。句子间要有清楚的时间、因果或转折关系，主语自然延续，不来回跳人物。朗读一遍：如果像资料摘录或翻译腔，就整段重写，不靠增加连接词补救。页面只显示地点、材料日期和原始链接，证据类型和依据留在后台数据，不显示“看依据”或核验过程。一个日常细节足以说明一个生活问题即可。读感以第001期澡堂镜面广告、南非送水车、育儿津贴为例。勿为罕见或戏剧性而选稿，勿用抽象结论收尾。统计需要解释多个指标才能明白的题目可以留待专题。

## 事实

搜索摘要提供线索。选入的每项说法都必须读到支持它的原文。区分记者所见、当事人判断、经营者自述和官方规定。个人经历只适用于当事人。全国趋势需统计，义务或权利需当前官方规则。规则与医疗等高影响主张核对可靠原始来源。对因果解释标明是谁的判断。不能读到正文就继续找别的材料。

每个来源 evidence 保存关键段落简述、数据表号或条款位置，便于回查。不要复制全文。日期精确到原文可确认的程度，允许 YYYY-MM。不要把收录日写成素材发布日期。

## 发布

全部远端 GitHub 读写使用 GitHub Connector。开始读取本规则、data/world-notes.json 和 data/world-notes/index.json，按索引读近14天归档。当日归档已存在时验读页面，勿重新选稿或覆盖。

生成请求 data/world-notes-publish-request.json。requestId 使用唯一安全字符标识，payload 的 schemaVersion=1，reportDate=上海当天，items 长度必须为5。每条包含 id、title、body、location、materialDate、evidenceType、category（数据/规则/报道/个体）、sources、image。image 为对象，必须包含 https url、sourceUrl（图片所在原文页）、alt（中文画面描述）、credit（原署名）、caption（简短中文图注）。sources 每项包含 publisher、https url、evidence。id 稳定，推荐日期加主题英文短名。不得设置 initialEdition。

提交后等待 Publish World Notes Action 成功，回读当天归档、最新版和索引，确认 requestId 与条目一致。脚本 scripts/publish_world_notes.py 是结构校验依据。Action 一次提交写入三者，近14天按ID和标题去重。语义事实核验由写稿任务负责。

GitHub Actions 的机器人提交可能不会触发分支模式的 Pages 构建。确认归档成功后，通过 Connector 更新 data/world-notes-deploy-trigger.json，内容为 reportDate、requestId、verifiedAt。该正常提交触发站点构建。若重跑，先查是否已经存在同 requestId 的部署触发与成功的公开页面，避免重复写入。

待公开站点 https://aitestforbolin.github.io/aitestforbolin-Personal-blog/ 的 data/world-notes.json 和 data/world-notes/archive/YYYY-MM-DD.json 回读一致，再在会话返回今日标题和 world-notes/?date=YYYY-MM-DD 链接。未核到公开数据，报告部署待确认并继续检查或安全重试。不能用后台归档成功代替上线确认。

不发布一至四条的半期内容，不用旧稿或未核实内容凑数。扩展检索后仍不足五条时，保留上一期与真实日期，报告本次未完成及具体阻塞，并在本次任务内继续尝试恢复。来源大面积打不开时报告采集失败；程序或部署失败报告具体阶段，继续恢复。更正已发布事实需保留更正说明和版本记录。

首周保留实际启动、上线时间、原文可读性、合格条数与失败原因，观察持续可用性。用户读感反馈用于改进下一期。

## 网站阅读形式

首页参照 X 讯息：只展示本期五个标题，每个标题链接到当期阅读页的对应条目，另有整期入口。阅读页按顺序完整呈现五条，每条一张相关配图；电脑上左文右图，手机上标题、图片、正文依次排列，保留清晰标题和舒适正文行距。不要显示内容分类筛选、折叠依据或核验文字，保留来源原文链接。历史已发布期数按真实条数展示，不伪造五条。

## 2026-11-12 行文校准

读者反馈的是文字本身读起来奇怪，不是页面设计。原稿的问题是无用的英文全名、未解释的音译术语、人物切换与松散细节拼接。不要把“有具体细节”等同于罗列细节。

网球稿围绕“免费学球的孩子如何来到球场、找到装备”展开，删去创办者英文全名和无助主线的每次人数。节日稿围绕“去姐姐家过节前买什么礼物、为什么这样选”展开，解释额头点吉祥痣的习俗，删去无关的商贩质量评论。范文以 data/world-notes/archive/2026-11-12.json 最新修订正文为准。

## 2026-11-13 配图

每条正文配一张相关真实图片。选稿核实原文时一起选图：优先原报道内与该条人物、物件或地点直接相关的照片；公共机构活动页配图也可。不能只抓 og:image 而不检查，须打开图片核对画面与原图注，避开网站标识、广告和同文其他地区的照片。原报道无合适图片时，可寻找同地点的官方或开放许可图片，并明确标注为环境配图，不冒充当事人或现场。不使用 AI 生成的新闻现场图，不为方便找图牺牲选材质量。

记录图片原署名、来源页和中文图注；保留水印，不暗示拥有版权。使用发布方公开允许展示的图片、公开分享预览或有适用许可的图片；有禁止转载/外链等限制时换用合适的开放图片。默认链接发布方公开图片地址，不复制大图入仓库。提交前实际读取图片，确认可显示且不是防盗链占位图。后续验读公开阅读页时确认五张图片均成功加载（naturalWidth > 0）；结构校验通过不能代替图片可用性检查。不可用则找可用替代来源，记录具体阻塞，不捏造图片。

首页仍只展示标题。阅读页图片下方只留简短图注、图片署名与原文链接。图片可点击打开原文；若日后来源失效，显示去原文查看图片的入口，正文继续可读。历史无图期数继续正常显示，不修改旧新闻事实。本次为11月13日五条补图，保留既有标题、正文、来源、requestId和发布时间；版本记录为本次 Git 提交。
